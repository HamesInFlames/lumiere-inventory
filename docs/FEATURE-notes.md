# Feature Spec: Shared notes panel

Status: **planned** — ready for implementation.
Scope: full-stack but small — new `Notes` sheet tab, 3 API endpoints, one
frontend panel. Follows every existing pattern (sheet = truth, cache, SSE,
webhook/poll sync).

## 1. What the user wants

A notes area on the **right side of the dashboard** where staff can write
free-form notes ("order oat milk from the other supplier", "fridge 2 door
loose"). Notes are shared — everyone sees the same list, live — and persist in
the Google Sheet so managers can read them there too.

## 2. Data model — new `Notes` tab (sheet = source of truth)

| Column | Field | Notes |
|---|---|---|
| A | ID | `note-<random8>` generated by the server |
| B | Text | the note body (plain text) |
| C | By | staff name (existing "Your name" field, or 'staff') |
| D | Created | ISO timestamp |

- **Append-only + delete**: notes are added and deleted, never edited (keeps
  sync trivial — no cell-level conflicts). Deleting removes the row
  (`DeleteDimensionRequest` by row index found via ID, mirroring how
  `_rowNumber` works in sheetsStore).
- Server auto-creates the tab on boot via the existing `ensureTabs` helper
  (add `Notes` + header row if missing) — works for the already-live sheet,
  no manual migration needed.
- LocalStore mirror: `notes: []` array in the local JSON db, same shape.

## 3. Backend

Extend the store facade (`store.js`) and both backends with:
- `listNotes()` — included in the cache and refreshed by the same
  `refresh()` cycle (poll + webhook already cover sheet-side changes).
- `addNote(text, by)` — server generates ID + timestamp, appends
  (`values.append` for Sheets), updates cache, `_emit({type:'notes-updated', notes})`.
- `deleteNote(id)` — remove row / array entry, update cache, emit.

Routes (auth-guarded like the rest):
- `GET /api/items` → add `notes` to the existing response (no new fetch on load).
- `POST /api/notes` — body `{text, by}`; 400 on empty/whitespace text; trim;
  cap length at 500 chars.
- `DELETE /api/notes/:id` — 404 if unknown.
SSE: new `notes-updated` event carrying the full notes array (small), plus
notes included in the existing `full-refresh` flow.

## 4. Frontend

### Desktop (`lg:` ≥1024px) — right column
`main` becomes `lg:flex lg:gap-4 lg:max-w-4xl` (bump from max-w-2xl only at
lg): the item list keeps its current width; an `<aside>` (`lg:w-72 shrink-0`)
sits to its right, sticky (`lg:sticky lg:top-<header height>`) so notes stay
visible while scrolling items.

### Mobile (< 1024px) — same panel as a bottom sheet
No right side exists on phones. Add a **Notes** button in the header meta row
next to Share (same styling, note-count badge like `Notes (3)` when > 0).
Tapping opens the panel as a bottom sheet (reuse the ShareSheet pattern:
fixed inset overlay, `items-end`, white card, backdrop-closes).

### The panel itself (one component, `NotesPanel.tsx`, used in both places)
- Title "Notes" (ink, sans — no gradient; the wordmark stays the only gradient
  text).
- Composer at top: textarea (2 rows, autosizes up to ~6) + "Add" button
  (ink bg/white text, disabled when empty). Posts with the header "Your name"
  value as `by`. Optimistic append; rollback on error.
- List below, newest first: each note = white card with `brand.line` border —
  text (pre-wrap), then a meta line `James · Jul 5, 2:14 PM` in inkSoft with a
  small × delete button (confirm not needed; deletion is visible to all and
  recoverable by retyping). Empty state: "No notes yet." in inkSoft.
- Live: subscribe to `notes-updated` SSE events in App (alongside
  item-updated) and pass notes down as props; App owns notes state.

## 5. Edge cases

- Two people adding simultaneously: both append — no conflict by design.
- Delete of an already-deleted note: API returns 404; client just removes it
  locally on any 404 (it's gone either way).
- Sheet-side edits: someone editing a note's text directly in the sheet is
  picked up by webhook/poll refresh (allowed, even though the app only
  appends/deletes).
- Manual rows added in the sheet without an ID: refresh assigns... NO — skip
  rows with empty ID in `listNotes()` and log a warning; keep it simple.
- Note text with newlines is fine (textarea + pre-wrap + single-cell write).

## 6. Verification checklist

1. `npm run build` passes.
2. Local mode, headless browser at 1280px: right column visible, add a note
   (appears instantly + persists across reload), delete it; second browser
   page sees both changes live via SSE without reload.
3. At 390px: Notes button with count badge opens bottom sheet; add/delete
   works; Share still works.
4. Sheets mode smoke test (session has sheet access): boot server with env
   set → `Notes` tab auto-created with header; POST a note → row appears;
   DELETE → row gone. Clean up test rows.
5. No layout regression to the item list at 390/768px (aside is lg-only).

## 7. Out of scope

- Editing notes in-app, pinning, per-item notes, mentions, done/checkbox
  states — add later if asked.
